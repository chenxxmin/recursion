# 混合精度训练选项对比（fp32 / TF32 / bf16 / fp16+GradScaler）

> 整理日期：2026-08-31。背景：grokking 型实验（模运算递推、污损补全）训练特征是
> "train loss 很快到 ~0（记忆完成）→ 漫长平台期 → test acc 缓慢上升（泛化）"。
> 平台期驱动泛化的梯度信号极其微弱，是数值精度问题的主战场。

## 1. 四个选项的基本面

| 档位 | 指数/尾数 | 相对舍入误差 | L20 峰值 | 实测速度* | 实现 |
|---|---|---|---|---|---|
| fp32 | 8 / 23 bit | ~6e-6 % | ~60 TFLOPS | 1x（基准） | — |
| TF32 | 8 / 10 bit（仅截 matmul 输入，fp32 累加） | ~0.05 % | ~75 TFLOPS | **1.27x** | `ALLOW_TF32=true`（默认开） |
| fp16 + GradScaler | 5 / 10 bit | ~0.05 %（另有范围问题，scaler 解决） | ~148 TFLOPS | **~2x** | `USE_AMP=true, AMP_DTYPE=float16` |
| bf16 | 8 / 7 bit | ~0.4 % | ~148 TFLOPS | **~2x** | `USE_AMP=true`（默认）、`AMP_DTYPE=bfloat16` |

\* 实测环境：action 任务 d1024l4，bs512，P127 tr64/ood128，与另一实验共享 GPU（绝对值偏大，相对比可靠）。
数据管线 0.05s/epoch、eval 摊薄 0.24s/epoch，均可忽略；瓶颈纯在矩阵运算。

## 2. 已做的对比实验与结果

### 2.1 速度探针（`scripts/probe_speed.py`，2026-08-30）

| 档位 | s/epoch（共享卡） | 加速比 |
|---|---|---|
| fp32 | 31.4 | 1x |
| TF32 | 24.8 | 1.27x |
| bf16 | 15.8 | 1.99x（eval 同步 2.1x，峰值显存 ~-40%） |
| torch.compile | 失败（环境缺 `-lcuda`，未修复） | — |

另有批次级实证：batch_size 512→8192 每 epoch 耗时不变 → bs=512 时算力已饱和，**加大 batch 无加速**。

### 2.2 收敛模型续跑破坏性测试（decisive test，2026-08-31）

同一 checkpoint（d1024l4 len2 miss0.1，test 95.03%，train loss≈0.0008）恢复完整训练状态后跑 1 epoch：

| 精度 | 1 epoch 后 test acc | 结论 |
|---|---|---|
| fp32 | 95.13% | ✅ 安全 |
| TF32 | 95.13% | ✅ 安全 |
| bf16 | 89.42% | ❌ 每个 epoch 掉 ~6 点 |
| fp16+GradScaler | 89.26% | ❌ 与 bf16 几乎相同 |

真实事故佐证：B 续跑（bf16）20 epochs 从 95.0% → 0.8%（完全归零），之后缓慢重学回 ~50%。
评估（不训练）在 bf16 下无害：95.03% → 95.02%。

### 2.3 从零训练的 bf16 表现

- A2/深度扫描全部 bf16 从零跑：N3 可达 80~86%，grokking 仍能发生（与 fp32 的 d256l2 86.7/89.5 同量级）。
- 但 bf16 下出现多个崩溃/低分个案（l6 两 seed 停在 1%、d512l4 miss0.3 的 2.4%），**无法区分"真学不出"与"被噪声摁死"**。

### 2.5 fp32 vs bf16 从零训练对照（2026-09-01，决定性）

同一设置（d256l2 N3 miss0.1len1）逐 seed 对比（6000 epochs，fp32 开 TF32）：

| seed | fp32 | bf16 | 差值 |
|---|---|---|---|
| 17996 | 86.7（A1 基线） | 48.1 | -38.6 |
| 18318 | 89.5（A1 基线） | 30.0 | -59.5 |
| 34789 | 84.6 | 23.5 | -61.1 |
| 44536 | 66.7 | 28.1 | -38.6 |
| **mean** | **81.9** | **32.4** | **-49.5** |

**bf16 噪声税在该设置下达 ~50 个点，4 seeds 无一 grok（fp32 全 grok）。** 推论：

- bf16 从零训练**在小模型上同样不可靠**——之前 A2 d512l2 bf16 能到 85% 只是宽模型更抗噪；
- 所有 bf16 下得出的阴性/平庸结论（深度扫描 l4-l8、A2 放大）全部作废，需 fp32 重测；
- bf16 唯一剩余价值：大模型上的粗筛（仅取阳性）。

### 2.6 续跑安全性实证（2026-08-31 ~ 09-01）

同一批 d2048 checkpoint 两次续跑对照：bf16 续跑 20 epochs 摧毁模型（95.0→0.8%）；
fp32 续跑健康上涨（如 d2048l2 miss0.1 seed18318：90.1@800ep → 91.2@1960ep）。

### 2.4 关键阴性结果

- **fp16 不是有效中间档**：比 bf16 多 3 位尾数（噪声小 8 倍），破坏程度却几乎相同。
  → 破坏机制不是单纯的尾数随机噪声，更可能是 16-bit autocast 前向对权重/激活的系统性舍入，
  使 loss 在"舍入后的函数"上计算，梯度方向产生持续偏差。
- **放大 loss（GradScaler 思路）对 bf16 无效**：舍入误差是相对的，信号噪声同比放大，信噪比不变；
  且 Adam 的 m̂/√v̂ 归一化对梯度绝对尺度不敏感，缩放被整个吃掉。

## 3. 机理分析

系统噪声层级：`bf16 舍入(0.4%) ≳ mini-batch 采样噪声(~1%) ≫ fp32 舍入(~6e-6%)`。

- fp32 噪声远低于 batch 噪声地板，而所有历史 grokking 实验都在该地板上成功 → fp32 实证充足。
- bf16 噪声抬头超过地板，在低信号区（平台期/收敛后）反客为主。
- 放大器有两个：**Adam 归一化**（信号消失后更新仍保持 ~lr 幅度，变成随机游走）和
  **weight decay=1**（持续侵蚀权重，需真实梯度顶住）。16-bit 下二者叠加 → 快速塌毁。
- 注意 fp16==bf16 的实证表明"系统性方向偏差"成分大于"随机噪声"成分，机理细节待进一步定位。

## 4. 对实验的影响（操作规则）

| 场景 | 推荐 | 理由 |
|---|---|---|
| 日常训练 | TF32（默认已开） | 1.27x 白捡，实证安全 |
| 探索扫点找阳性 | 可用 bf16（2x） | **bf16 的假阳性不存在：grok 了就是真行** |
| 用失败下结论（"不可行"） | 必须 fp32 | **bf16 假阴性一大堆：没 grok 可能是被噪声摁死的** |
| 续跑（RESUME_FROM） | 已收敛必须 `USE_AMP=false`；早期（loss 大）可以 16-bit | 实测收敛模型 20 epoch 归零 |
| 纯评估/推理 | 任意 | 无梯度，无害 |

一句话：**bf16 用来找"哪里行"，别用来证"哪里不行"；一切结论 fp32。**
